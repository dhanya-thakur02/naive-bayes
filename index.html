Why Naive Bayes?

The fundamental idea: let probability vote

Naive Bayes is a machine learning algorithm that predicts a category — spam vs not spam, positive vs negative — by asking: "given the words in this text, which class was most likely to have produced them?" It answers that question using Bayes' Theorem.

It is called "naive" because it assumes every word's presence is independent of every other word, given the class. That assumption is almost never literally true — but it makes the math fast, the model tiny, and in practice the classifier still performs remarkably well.

Step 1 — Tokenization
1

Break the sentence into words

Lowercase, strip punctuation, split, and check each word against the vocabulary

The input is lowercased, punctuation removed, and split into tokens. Each token is checked against the trained vocabulary. Words never seen during training are Out-Of-Vocabulary (OOV) and contribute nothing to the score.

💡 OOV words have no learned statistics. Production systems use <UNK> tokens or subword tokenization (BPE) to soften this problem.
Step 2 — Prior Probabilities
2

What does the model believe before reading a single word?

P(class) = proportion of training documents with that label

Before looking at any words, the baseline guess is simply how common each class was in training. A 90/10 class split creates a strong pull toward the majority class — a real challenge with imbalanced datasets.

Step 3 — Word Likelihoods
3

How likely is each word, given the class?

P(w | c) = (count(w,c) + d) / (total tokens in c + d × |V|)

For every in-vocabulary word in the test sentence, the model looks up how often that word appeared in each class during training, smoothed by the Laplace constant d you set above.

⚠️ Zero smoothing alert: any word with 0 training count in a class gets P = 0. Since Naive Bayes multiplies likelihoods, a single zero can wipe out an entire class's probability.
💡 Laplace smoothing (d > 0) guarantees no probability is ever exactly zero, even for words unseen in one particular class.
Step 4 — Combining the Evidence
4

Decimal multiplication vs. log-space addition

Two mathematically equal ways to compute the same joint probability

Naive Bayes multiplies the prior by every word's likelihood. Multiplying many small decimals quickly underflows to 0.0 on real hardware — which is why production systems work in log-space, where multiplication becomes addition.

Method B — Log addition (recommended)

⚠️ Underflow: multiplying twenty values like 0.002 can produce a number below 10⁻⁵⁰ — computers round this to 0.0. Log values like −34.82 are handled easily and safely.
# Why log-space works # log(P(A) × P(B)) = log P(A) + log P(B) import math log_score = math.log(prior) for word in tokens: log_score += math.log(likelihood[word]) # addition, not multiplication
Step 5 — Normalised Result
5

Turning log-scores into a probability

Posterior = joint score ÷ sum of all joint scores (via log-sum-exp)
💡 Bayes' Rule says: Posterior ∝ Prior × Likelihood. Dividing by the sum across all classes converts raw joint scores into a true probability distribution that sums to 1.
